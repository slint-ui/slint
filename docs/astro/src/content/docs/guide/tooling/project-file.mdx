Use a `slint-project.json` file to configure your project's main file and compiler settings, such as include paths.
To apply these settings, pass the project directory to the compiler.

## Location

Place `slint-project.json` inside the project directory.
For example, passing `/projects/app` loads `/projects/app/slint-project.json`.
Compiling `/projects/app/ui/main.slint` directly doesn't load a project file.

## Example

```json
{
    "slint-edition": "1.19",
    "main": "ui/main.slint",
    "include-paths": ["ui/shared"],
    "library-paths": {
        "widgets": "ui/widgets"
    }
}
```

The file uses JSON syntax and accepts `//` and `/* */` comments.
`slint-edition` is required.
When you pass a project directory to the compiler, `main` is required, too.
All other settings are optional.

## Settings

| Setting | Type | Description |
|---------|------|-------------|
| `slint-edition` | string | Required. The Slint release whose language behavior your project uses, such as `"1.19"`. See [Editions](../../language/concepts/editions/). |
| `main` | string | The `.slint` file to compile when you pass the project directory. See [Compiling a Project](#compiling-a-project). |
| `include-paths` | array of strings | Directories to search for imported `.slint` files. |
| `library-paths` | object | Maps a library name to a file or directory, for `@library` imports. |
| `experimental-features` | array of strings | The [experimental features](https://snapshots.slint.dev/master/docs/slint/guide/experimental/overview/) to turn on, such as `["interfaces", "match"]`. |
| `metadata` | object | This value is ignored by the compiler. It may be used by other tooling to store per-project configuration. |

Slint resolves relative paths against the directory that contains the project file.

## Which Setting Wins

A setting can come from three places, listed from highest to lowest priority:

1. An option passed to the API or the command line, such as an include path.
2. The project file.
3. A compiler default.

:::note
You can't set `slint-edition` through the API or the command line; it only comes from the project file.
:::

## Compiling a Project

To compile your project, first set `main` to the main `.slint` file of your application:

```json
{
    "slint-edition": "1.19",
    "main": "ui/main.slint"
}
```

Then, pass the project directory wherever a `.slint` file is expected:

<Tabs syncKey="dev-language">
<TabItem label="Rust" icon="seti:rust">
```rust
// build.rs
fn main() {
    slint_build::compile(".").unwrap();
}
```

Settings on <LangRefLink lang="rust-slint-build" relpath="struct.CompilerConfiguration">`CompilerConfiguration`</LangRefLink> win over the project file.
Cargo rebuilds your crate when the project file changes.
The `slint!` macro doesn't load a project file.
</TabItem>
<TabItem label="C++" icon="seti:cpp">
```cmake
slint_target_sources(my_application .)
```

The generated header is named after the main file, so you still `#include "main.h"`.
CMake rebuilds your target when the project file changes.
CMake passes the `SLINT_STYLE` variable to the compiler as `--style`.
For more details, see <LangRefLink lang="cpp" relpath="cmake-reference/slint-target-sources/">`slint_target_sources`</LangRefLink>.

The interpreter also reads the project file when you load a project directory at run time.
</TabItem>
<TabItem label="NodeJS" icon="node">
```javascript
import * as slint from "slint-ui";

let ui = slint.loadFile(".");
```

The options you pass to <LangRefLink lang="nodejs" relpath="api/functions/loadFile/">`loadFile`</LangRefLink> win over the project file.
</TabItem>
<TabItem label="Python" icon="seti:python">
```python
import slint

ui = slint.load_file(".")
```

The arguments you pass to `slint.load_file` win over the project file.
</TabItem>
</Tabs>

The `slint-compiler` command line tool accepts directories, too:

```bash
slint-compiler . -o main.h
```

## Editor Support

The Slint language server discovers the project files for your open documents.
When you edit multiple projects, it combines their settings.
The live preview uses the project root that the language server selects for the previewed file.

When you open a `.slint` file in the Visual Editor without `--project-root`, the file's parent directory becomes the project root.
To select another root, pass `--project-root <directory>` to the Visual Editor or the [viewer](../slint-viewer/).
The `.slint` file you specify stays the entry point.
