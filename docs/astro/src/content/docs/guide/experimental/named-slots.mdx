title: Named Slots
description: Experimental named slots for multiple content insertion points.
---

A `slot` is a named insertion point where a component renders content supplied by its user.
It generalizes the built-in `@children` placeholder: instead of a single anonymous block of children, a component can declare several slots and place each one at a distinct location in its own layout.

> **Note**: named slots are experimental and subject to change.
> Enable them with the `named-slots` [experimental feature](../overview/).
> Tracking issue: [slint-ui/slint#6258](https://github.com/slint-ui/slint/issues/6258).

## Declaring a slot

Use the `slot` keyword inside a component to declare a slot, then render it at the desired location by writing the slot's name as an empty element.

```slint
export component Base inherits Rectangle {
    slot header;
    slot footer;

    VerticalLayout {
        header {}      // render site for the `header` slot
        @children      // the default slot
        footer {}      // render site for the `footer` slot
    }
}
```

A declared slot must be rendered exactly once.
`@children` continues to work as before and represents the default, unnamed slot.

## Assigning a slot

The user of a component fills a slot with the `<<` operator, naming the slot on the left and the content on the right.
Content that is not assigned to a named slot goes to `@children`, as usual.

```slint no-test
export component App inherits Rectangle {
    Base {
        header << Rectangle { background: blue; }
        Text { text: "Main Content"; }   // goes to @children
        footer << Rectangle { background: gray; }
    }
}
```

Assigning an untyped slot is optional.
An unassigned untyped slot renders its [default content](#default-content), or nothing if it has none.
[Scalar typed slots](#typed-slots) require a supplied component.

## Default Content

Give an untyped slot default content with `<<` in its declaration.
The component shows the default until a caller assigns the slot.
An assignment replaces the whole default, including its layout constraints.

```slint
export component Panel inherits Rectangle {
    slot heading << Text { text: "Untitled"; }
    VerticalLayout {
        heading { }
        @children
    }
}

export component App inherits Window {
    VerticalLayout {
        Panel {
            Text { text: "Shows the default heading"; }
        }
        Panel {
            heading << Text { text: "Project"; }
            Text { text: "Details"; }
        }
    }
}
```

Assign `{ }` to remove the default content without replacing it:

```slint no-test
Panel {
    heading << { }
}
```

The default content is a single element.
Wrap an `if` or `for` in an element to use it as default content.
Default content can't contain slot placeholders or `@children`.
A `Tab` in a `TabWidget` and a `Menu` in a `ContextMenuArea` or `SystemTrayIcon` can't be default content;
declare them as children instead.

Replacing the default removes its elements, so references to them from outside the default content are errors:

```slint no-test
component Foo inherits Rectangle {
    slot bar << label := Text { text: "Default"; }
    Text { text: label.text; }   // error
    bar { }
}
```

References between elements inside the same default content are allowed.
For shared state, declare a property on the component and bind both the default content and other elements to it.

A slot that's forwarded to another component's slot can't have default content.
Set the default on the target slot instead.
Typed slots don't support default content yet.

### Filling Inherited Slots

A derived component fills an inherited untyped slot with `<<` at its root.
The assignment becomes the slot's default content: the slot stays open, and callers of the derived component can replace it.
Assigning `{ }` removes the inherited default and also leaves the slot open.

```slint
component Base inherits Rectangle {
    slot content << Text { text: "Base default"; }
    VerticalLayout {
        content { }
    }
}

component Derived inherits Base {
    content << Text { text: "Derived default"; }
}

export component App inherits Window {
    VerticalLayout {
        Derived { }   // shows "Derived default"
        Derived {
            content << Text { text: "Caller"; }
        }
    }
}
```

Don't redeclare an inherited slot or place it again in the derived component.
The slot keeps the position its base component gives it.

## Referencing a slot

The name bound to a scalar slot is a regular element reference, so its properties can be read like any other element.

```slint no-test
export component App inherits Rectangle {
    Base {
        header << Rectangle { height: 8px; }
        out property <length> header-y: header.absolute-position.y;
    }
}
```

## Forwarding a slot

A component can forward one of its own slots to a slot of a child component, again with the `<<` operator.
This lets a wrapper expose a nested component's slots as its own.

```slint
export component SlotHost inherits Rectangle {
    slot host-header;
    VerticalLayout {
        host-header {}
        @children
    }
}

export component Outer inherits Rectangle {
    slot header;
    SlotHost {
        host-header << header;   // forward Outer's `header` into SlotHost's `host-header`
        @children
    }
}
```

## Full example

```slint
export component Card inherits Rectangle {
    slot header;
    slot footer;

    VerticalLayout {
        header {}
        @children
        footer {}
    }
}

export component App inherits Window {
    Card {
        header << Text { text: "Title"; }
        Text { text: "Body content"; }
        footer << Text { text: "Footer"; }
    }
}
```

## Typed Slots

Declare `slot <InterfaceName> name;` when a component needs to interact with supplied content through an [interface](./interface).

The host can bind interface inputs, read outputs, modify `in-out` properties, call public functions, and connect callbacks.
Members outside the interface aren't available through the host's slot reference.

```slint
interface Action {
    in property <bool> enabled;
    callback activated();
}

component ActionHost inherits Rectangle {
    in property <bool> enabled: true;
    callback activated();

    slot <Action> action;
    action {
        enabled: root.enabled;
        activated => { root.activated(); }
    }
}

component PointerAction {
    in property <bool> enabled;
    callback activated();

    Text { text: "Click me"; }
    TouchArea {
        enabled: root.enabled;
        clicked => { root.activated(); }
    }
}

export component App inherits Window {
    width: 200px;
    height: 80px;

    ActionHost {
        action << PointerAction { }
        activated => { debug("Activated"); }
    }
}
```

The supplied component must provide the interface's members with matching types, visibility, and function signatures.
Pure interface functions require pure implementations.
An explicit `implement` declaration isn't required.
Members can be declared directly, inherited, or delegated with `implement Action <=> child`.

A typed slot requires exactly one component when its host is instantiated.
A derived component can leave the slot open for its caller.
Unlike an untyped slot, a typed slot that a derived component fills is closed to that component's callers.
When forwarding between two typed slots, both must declare the same interface.

Typed placeholders accept property bindings, callback connections, and property change handlers, but not child elements or new declarations.
Defining handlers for the same callback in both the placeholder and supplied component is an error.
Property bindings follow the existing priorities; more local bindings take precedence.

## Collection Slots

Declare `slot <[implements Entry]> entries;` to accept multiple components that implement an interface.
Enable the `interfaces` experimental feature when using an interface type.
Collection slots support three constraints:

| Declaration | Accepted Children |
| --- | --- |
| `slot <[*]> entries;` | Any component, without an interface requirement. |
| `slot <[implements Entry]> entries;` | Any component satisfying the `Entry` interface. |
| `slot <[Entry]> entries;` | The component or built-in element type `Entry`, including components inheriting it. |

An unrelated component with matching properties doesn't satisfy a component type constraint.
An interface constraint doesn't require explicit `implement` declarations.
Wildcard entries expose the standard element properties; typed entries also expose their constraint's public members.
Scalar typed slots keep the syntax `slot <Entry> entry;`, where `Entry` is an interface.

The `default` qualifier routes ordinary children into the collection instead of `@children`.
Fill named collections with repeated assignments such as `entries << EntryView { }`.
A component can declare multiple collection slots, including one default collection, alongside scalar slots.

Expand the supplied components with `for`, applying bindings and callback handlers to each component:

```slint
interface Entry {
    in property <int> position;
    in property <bool> selected;
    callback activated();
}

component EntryGroup {
    in-out property <int> current-index: -1;
    out property <int> count: entries.length;
    default slot <[implements Entry]> entries;

    HorizontalLayout {
        for entry[index] in entries: entry {
            position: index;
            selected: index == root.current-index;
            activated => { root.current-index = index; }
        }
    }
}
```

The expansion places existing supplied components without replacing their type or visuals.
The child and optional index variables are available only inside the expansion.
`entries.length` tracks the number of supplied components, including changes to a supplied repeater's model.
Collection lengths and indexes are read-only.

Callers can't assign properties or callback handlers managed by the expansion.
Bindings in the supplied component's implementation remain available as defaults; property change handlers from both sides are combined.

### Collection Limits

- Each collection requires exactly one expansion in its declaring component.
- Expansions accept bindings, two-way bindings, callback connections, and property change handlers, but no child elements or member declarations.
- Supply static components or a single `for` loop; conditional children and mixtures of static children and repeaters aren't supported.
- Forwarding collection slots or `@children` into collections isn't supported.
- A derived component can supply collection children, but its callers can't append additional children to that collection.

`@children` remains supported separately; collection slots don't yet replace its forwarding behavior.

### Known Issue

An empty assignment such as `entries << { }` can be accepted without removing entries supplied by a derived component.

## Current limitations

The named slot feature is in its early stages. The following restrictions apply:

- The name `children` is reserved for the default slot. Use `@children`, or declare a default collection slot.

- A declared slot must be rendered exactly once, and it may not be placed inside a `for`, `if`, or `match` element.

- A slot cannot be placed inside a `PopupWindow` or a `ComponentContainer`.

- Slot assignment and forwarding are only valid on components, and each scalar slot may be assigned at most once.
