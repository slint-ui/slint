---
title: Repeated Child Constraints
description: "Experimental: count `if` and `for` children toward the size of their parent."
---

A child created with `if` or `for` doesn't count toward the size of a non-layout parent,
while a static child does.
The exception is a `Flickable` or a `ScrollView`: there a layout counts whether it is
static or repeated, while anything else counts for nothing, and neither do `ListView` rows.
Turn this feature on to make a repeated child count like a static one everywhere
([#407](https://github.com/slint-ui/slint/issues/407)):

```slint
container := Rectangle {
    // With the feature on, container.min-width is 200px, as it would be for a
    // static child. Without it, the container reports no constraint at all.
    if true: Rectangle { min-width: 200px; }
}
```

As with a static child, the child's own `width` or `height` doesn't count.

> **Note**: this is a breaking change, which is why it is opt-in for now.
> A child that sizes itself from the parent it now constrains forms a binding loop,
> which the compiler reports as an error ([#13972](https://github.com/slint-ui/slint/issues/13972)).
> Set `x` or `y` on such a child to keep it out of its parent's size,
> as a static child can.

Experimental features are turned on together, so enabling this one enables the others too.
See [the overview](../overview/).
It becomes the default once Slint supports editions.
