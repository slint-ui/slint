---
title: Mocking Data
description: Populating your UI with placeholder data while designing, without shipping it in the compiled application.
---

While designing a UI, it's useful to see it filled with realistic-looking data before any business logic exists to provide it.
Slint offers two building blocks for this: `Platform.uses-mock-data` and `@from-json(...)`.

## `Platform.uses-mock-data`

[`Platform.uses-mock-data`](../../../../reference/platform/#uses-mock-data) is `true` when the `.slint` file is previewed on its own,
for example with `slint-viewer` or an editor's live preview.
It's `false` once a host application written in Rust, C++, JavaScript, or Python drives the file.
It's a compile-time constant, so the compiler removes any branch that depends on it.
Mock data never ends up in your compiled application.

```slint
import { ListView, VerticalBox } from "std-widgets.slint";

export struct Contact {
    name: string,
    online: bool,
}

export component Example inherits Window {
    width: 150px;
    height: 150px;

    in property <[Contact]> contacts: Platform.uses-mock-data ? [
        { name: "Alice", online: true },
        { name: "Bob", online: false },
        { name: "Carol", online: true },
    ] : [];

    VerticalBox {
        ListView {
            for contact in root.contacts : Rectangle {
                height: 24px;
                Text {
                    text: contact.name;
                    color: contact.online ? green : gray;
                }
            }
        }
    }
}
```

In a host application, `Platform.uses-mock-data` is `false` and the compiler removes the ternary's first branch.
The placeholder data never ships.

## `@from-json(...)`

Typing placeholder values into a `.slint` file works for a couple of rows, but gets unwieldy for anything larger.
You also can't share them with a designer or generate them with a script.
`@from-json("file.json")` reads a JSON file at compile time instead,
and converts its whole content to the type of the property it's assigned to:

```slint
export struct Contact {
    name: string,
    online: bool,
}

export component Example {
    property <[Contact]> contacts: @from-json("snippet-data/contacts.json");
}
```

Select a value inside the file with member access, and an element of a JSON array with an integer literal index:

```slint
export component Example {
    property <string> greeting: @from-json("snippet-data/data.json").greeting;
    property <int> count: @from-json("snippet-data/data.json").stats.visitors.count;
    property <string> first-tag: @from-json("snippet-data/data.json").tags[0];
}
```

The conversion handles arrays and structs recursively,
so a JSON file can describe entire lists of mock records, not just single values.
Mock records can include pictures too:
an `image` is a path relative to the JSON file, or the image content as a `data:` URI.
The file path must be a plain string literal, since the file is read once, at compile time.
See the [`@from-json`](../../../../reference/language/expressions/#from-json) reference for the full conversion and lookup rules.

## Combining both

Use the two together: `@from-json(...)` supplies realistic mock data,
and `Platform.uses-mock-data` loads that data only while previewing.
A conditional expression always needs an else branch, so give it an empty default for the real application:

```slint
export struct Contact {
    name: string,
    online: bool,
}

export component Example {
    in property <[Contact]> contacts: Platform.uses-mock-data ? @from-json("snippet-data/contacts.json") : [];
}
```

The preview shows the data from `contacts.json`.
In a real application, `Platform.uses-mock-data` is `false`,
so the compiler removes the `@from-json` call together with the branch that contains it.
Nothing from `contacts.json` ends up in the final binary.

## Mocking several properties at once

Repeating `Platform.uses-mock-data ? ... : ...` on every property that needs placeholder data gets noisy.
Use a [`states`](states/) block instead.
Give every property its real, empty-by-default value as its normal binding.
Then add a single state that overrides all of them while `Platform.uses-mock-data` is `true`.

```slint
export struct Contact {
    name: string,
    online: bool,
}

export component Example inherits Window {
    in-out property <string> heading: "My App";
    in-out property <[Contact]> contacts: [];

    states [
        mock-data when Platform.uses-mock-data: {
            heading: "My App (preview)";
            contacts: @from-json("snippet-data/contacts.json");
        }
    ]
}
```

`Platform.uses-mock-data` now appears once, no matter how many properties the `mock-data` state sets.
Since it's a compile-time constant, the compiler removes the whole state from the real application, including the `@from-json` call.
