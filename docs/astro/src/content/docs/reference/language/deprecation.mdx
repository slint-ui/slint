---
title: Deprecation
description: Marking a property, callback, or function as deprecated with @deprecated.
---

The `@deprecated` annotation marks a property, callback, or function as deprecated.
The compiler warns wherever the member is used from outside the component that declares it,
and the warning carries a message pointing at the replacement:

```slint
component Inner {
    in-out property <int> new-prop;
    @deprecated("") in-out property <int> old-prop <=> new-prop;
}

export component Example {
    inner := Inner { }
    // Warning: The property 'old-prop' has been deprecated. Please use 'new-prop' instead
    out property <int> value: inner.old-prop;
}
```

The annotation affects diagnostics only.
A deprecated member keeps the type, visibility and behavior its declaration gives it,
and the compiled result is the same as without the annotation.

## Form

`@deprecated` precedes the declaration, ahead of any visibility or purity modifier,
and takes the message in parentheses:

```slint no-test
@deprecated("Compute it from 'new-prop' instead") in-out property <int> older-prop: 42;
@deprecated("Use 'new-callback' instead") callback old-callback();
@deprecated("Use 'new-function' instead") public pure function old-function() -> int { 1 }
```

- The message is mandatory.
  `@deprecated` without parentheses is a compile error.
- The message must be a plain string literal.
  A `\{}` template expression in it is a compile error.
- A declaration may carry `@deprecated` only once.

## Derived Messages

An empty message, `@deprecated("")`, derives the message from the declaration's
[two-way binding](../two-way-bindings/) target, as `Please use 'target' instead`:

```slint no-test
@deprecated("") in-out property <int> old-prop <=> new-prop;
```

- The declaration must have a two-way binding.
  Without one there is nothing to derive from, which is a compile error.
- The target must be a property of the same element that isn't `private`,
  so that the replacement the message names is reachable from where the warning appears.
  Any other target is a compile error, and needs an explicit message instead.
- The derived message keeps the whole path to the target, such as `a-struct.field`,
  minus a leading `self` or `root`.
- A [function](../functions/) has no two-way binding to derive from,
  so `@deprecated` on a function requires a non-empty message.

## Warnings

Using a deprecated member is a warning, never an error, so code written against it keeps compiling.
Reading it, assigning to it, binding it on an element, aliasing it with `<=>`, animating it,
calling it, and setting a handler for it each warn.

Uses within the component that declares the member don't warn,
since that component still has to implement it.
