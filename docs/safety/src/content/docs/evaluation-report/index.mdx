The Evaluation Report analyzes how Slint SC is used, what can go wrong in that use, and how much confidence each part needs as a result.
The chapters build on each other, so read them in order.

* [Use Cases](/evaluation-report/use-cases/): how Slint SC is used in a project.
* [Potential Errors](/evaluation-report/potential-errors/): what can go wrong in the compiler and the runtime, and the measure or constraint that covers each error.
* [Tool Classification](/evaluation-report/tool-classification/): the confidence level each tool needs, derived from the potential errors and their detection.
* [Qualification Method](/evaluation-report/qualification-method/): how the compiler and the runtime reach that confidence.
* [Safety Analysis](/evaluation-report/safety-analysis/): the safety-oriented analysis of the software architecture.

How Slint SC is built and tested is in the [Qualification Plan](/qualification-plan/).
