title: ISO 26262-6 Method Tables
description: Which methods of the ISO 26262-6 tables Slint SC applies at ASIL B, and why.
---

Each table lists the methods of one table of ISO 26262-6, with the recommendation at ASIL B:
`++` highly recommended, `+` recommended, `o` no recommendation.
See [Status](/norm-mapping/#status) for how to read the Applied column.

## Table 1: Coding Guidelines

| No. | Topic | ASIL B | Applied | How |
| --- | --- | --- | --- | --- |
| 1a | Enforcement of low complexity | ++ | Partly applied | The runtime is about 700 lines. No complexity limit is set or checked yet. |
| 1b | Use of language subsets | ++ | Partly applied | No unsafe code, no standard library, and no `alloc`; see [Coding Standards](/safety-plan/coding-standards/#slint-sc-runtime). Panicking operations and lossy casts aren't excluded yet. |
| 1c | Enforcement of strong typing | ++ | Applied | Rust is strongly typed, with no implicit conversions. |
| 1d | Use of defensive implementation techniques | + | Partly applied | [`slint.runtime.avd.buffer-size-check`](/runtime/safety-analysis/#slint.runtime.avd.buffer-size-check). Whether arithmetic overflow panics or wraps depends on the integrator's build profile. |
| 1e | Use of well-trusted design principles | + | Applied | The principles of Table 6; see [Design Principles](/safety-plan/coding-standards/#design-principles). |
| 1f | Use of unambiguous graphical representation | ++ | Not applied | Slint SC uses no graphical modelling. |
| 1g | Use of style guides | ++ | Partly applied | CI runs clippy with warnings as errors; see [Coding Standards](/safety-plan/coding-standards/#slint-sc-runtime). Coding Standards doesn't name the formatting rules yet. |
| 1h | Use of naming conventions | ++ | Applied | Rust's naming lints, which the CI clippy run turns into errors. |
| 1i | Concurrency aspects | + | Applied | The runtime has no threads and no interrupts; see [Dynamic Design](/safety-plan/architecture/#dynamic-design). |

## Table 3: Architecture Principles

| No. | Principle | ASIL B | Applied | How |
| --- | --- | --- | --- | --- |
| 1a | Appropriate hierarchical structure | ++ | Partly applied | [Software Units](/safety-plan/architecture/#software-units). The structure inside the runtime isn't described yet. |
| 1b | Restricted size and complexity | ++ | Applied | The runtime is about 700 lines. |
| 1c | Restricted size of interfaces | + | Applied | The generated component has a constructor, `render_rgb8`, property accessors, and `dispatch_touch_event`; see [Generated Code](/reference/generated-code/). |
| 1d | Strong cohesion | ++ | Partly applied | The runtime renders, and the generated code holds the state of one component. The argument isn't written up yet. |
| 1e | Loose coupling | ++ | Partly applied | The generated code depends on nothing but the runtime; see [`sls.gen.output`](/reference/generated-code/#sls.gen.output). It calls the runtime through the hidden `private_unstable_api` module. |
| 1f | Appropriate scheduling properties | ++ | Applied | Slint SC has no scheduler; every call runs on the caller's thread. See [Dynamic Design](/safety-plan/architecture/#dynamic-design). |
| 1g | Restricted use of interrupts | + | Applied | Slint SC uses no interrupts. |
| 1h | Appropriate spatial isolation | + | Not applied | The integrator isolates Slint SC from other software; see [`slint.aou.freedom-from-interference`](/user-manual/#slint.aou.freedom-from-interference). |
| 1i | Appropriate management of shared resources | ++ | Applied | The only shared resource is the frame buffer, which the application owns and lends to `render_rgb8`; see [Properties](/safety-plan/architecture/#properties). |
