Slint SC is the "ISO 26262 compliant subset" of Slint.
It doesn't exist yet, and these documents are a Work In Progress.

## Purpose of These Documents

Together they make up the Safety Manual, the qualification package for Slint SC.

Read the [User Manual](/user-manual/) if you build with Slint SC.
It's the only one that changes what you do, and every rule in it is a condition of the qualification holding.
The [Reference](/reference/) states what your `.slint` code means, and how the code built from it behaves.

The rest record how Slint SC is built and tested, so an assessor can check the work.

## Documents

* **[User Manual](/user-manual/)**: what you must do, and not do, so your use of Slint SC stays covered by its qualification.
* **[Reference](/reference/)**: the Slint language specification, APIs, specification of behavior.
* **[Qualification Plan](/qualification-plan/)**: how we organize, develop, test, and release Slint SC, and the architecture we do it to.
* **[Tool Evaluation Report](/evaluation-report/)**: how the compiler and `slint-sc-coverage` are used, what can go wrong in them, and the confidence each one needs.
* **[Component Documentation](/component-documentation/)**: the specification of the runtime as a qualified component, and what can go wrong in it.
* **[Qualification Report](/qualification-report/)**: the outcome of qualifying the tools and the runtime, with the test results, the traceability matrix, and the measured coverage.
