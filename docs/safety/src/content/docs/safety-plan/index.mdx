The Safety Plan lists the safety activities of Slint SC.
Where another chapter of this manual already describes an activity, the plan links to that chapter rather than repeating the description.

## How Slint SC Is Developed

SixtyFPS GmbH delivers Slint SC to integrators as a software component.
Integrators build Slint SC into their own products, at up to ASIL B.
We don't build a product ourselves, so there's no vehicle function or hardware on our side.
The integrator builds the product and certifies it.

Slint SC consists of a runtime and tools, and different parts of ISO 26262 apply to the runtime and to the tools:

* The `slint-sc` runtime becomes part of the integrator's product.
  The runtime is developed under ISO 26262-6 as a [Safety Element out of Context](/safety-plan/standards-compliance/#integrity-level) (SEooC).
  See [Tailoring](/safety-plan/standards-compliance/#tailoring) for what developing the runtime as an SEooC changes.
* The Slint compiler and `slint-sc-coverage` are tools.
  They run while the integrator builds and tests the product, and aren't part of the product.
  ISO 26262-8 Clause 11 covers them; see the [Tool Evaluation Report](/evaluation-report/).

## Release Scope

Each release states which language subset and runtime features the release covers.
The compiler rejects everything outside that subset.
The subset is what the [Reference](/reference/) lists.
