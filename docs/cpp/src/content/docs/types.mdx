The following table summarizes the mapping.

## Structures

For each exported `struct` in your `.slint` code, the Slint compiler generates a `class` with the same data members in the same order.
In the names of these classes and their data members, the compiler replaces dashes (`-`) with underscores (`_`).
If a name is a C++ keyword, such as a field `delete`, the compiler appends an underscore: `delete_`.

For example, consider this `struct` in a `.slint` file:

```slint
export struct MyStruct {
    foo: int,
    bar: string,
}
```

The Slint compiler generates the following C++ class:

```cpp
class MyStruct {
public:
    int foo;
    slint::SharedString bar;
};
```

If you use an anonymous struct, you work with a `std::tuple` of its field values, in alphabetical order.
For example, consider this property:

```slint
export component Example {
    in-out property <{score: int, name: string}> player;
}
```

The generated accessors take and return a `std::tuple<slint::SharedString, int>`:

```cpp
example->set_player({"Foo", 100});
auto [name, score] = example->get_player();
```

:::note
`name` comes first, although the property declares `score` first.
:::

## Enums

For each exported `enum` in your `.slint` code, the Slint compiler generates an `enum class`.
The values keep their declaration order and are converted to CamelCase.

For example, consider this `enum` in a `.slint` file:

```slint
export enum MyEnum { alpha, beta-gamma, omicron }
```

The Slint compiler generates the following C++ type:

```cpp
enum class MyEnum { Alpha, BetaGamma, Omicron };
```
